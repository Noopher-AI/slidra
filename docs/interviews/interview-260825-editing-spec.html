編輯功能 spec 設計

使用者訪談紀錄 · 2026-08-25 · Slidra（SVG-first 簡報編輯器）· 來源：session 逐字檔

本次做成的決定

  • 範圍：一份大 spec，收「物件／幾何／樣式／組織」骨幹——插入刪除、搬移縮放旋轉、樣式、疊置順序、群組、對齊、剪貼簿、投影片增刪複製重排、復原、範本。表格、圖表另開票；轉場效果全簡報只有一種，存 project.json。
  • 幾何模型：每個元素包一層 <g transform>「相框」——搬移、旋轉、群組一個機制解決，任何軟體原樣打開都正確。
  • 文字框：Slidra 自己算斷行，寫成多行 <tspan> 存進 SVG。
  • 縮放語意：Keynote 做法——拉邊改框寬文字重排，拉角等比縮放含字級，群組一律等比。
  • SVG 合規性：嚴格格式，不合規拋錯；另有使用者主動執行的 normalize 轉換命令。
  • 復原模型：一條時間軸，人的每個操作一格，agent 一回合綁成一格；用快照實作，關檔就清空。
  • 併發凍結：agent 動手期間凍結編輯，從它第一條命令凍到回合結束，思考期間不擋。
  • 範本與鎖定：範本是死的 SVG，套用＝整份複製；元素帶鎖定標記，UI 完全擋住，CLI 拒絕但留 --force。不做母片同步、不做換範本，交給 agent 掃頁改。
  • 動態文字：{{ slide_number }} 直接寫在內文，顯示時才替換；只做變數替換不做邏輯，先三個變數。
  • 資產匯入：agent 可用絕對路徑或 URL 匯入，一律進 assets/，匯入時驗證真實媒體格式。
  • 命令顆粒度：一條命令吃多個元素，一次操作一格復原。
  • 樣式命令：通用的 element style set，屬性名直接用 SVG 屬性名，但走白名單——擋的是幾何不變式，不是安全。
  • 元素種類：固定清單＋任意 path（path 只能整塊操作，不支援節點編輯）。
  • 複製與效果：效果跟著元素走，插在目標清單最後。
  • 剪貼簿範圍：只在同一份簡報內＋支援從系統剪貼簿貼入圖片。
  • 換範本：不提供，讓 agent 幫忙搬內容。
  • 另開的票：字型打包進 .slidra、表格、圖表、跨簡報搬運。

（這場對話的節奏值得先說一句：使用者多次打斷 AskUserQuestion，要求「用 15 歲聽得懂的話跟我說清楚」「以白話方式跟我說一下各個方案的優劣」——每次都逼出一輪更平實的解釋，而整場對話最大的特徵是大量的反轉：先選的答案常常在下一輪被使用者整個推翻。以下逐一標註。）

開場：從「一般 slide app 的編輯功能」開始

使用者

我想要接續一個新的 spec，目標是做到一般 slide app 可以做到的編輯功能（如 PPT、Keynote），你思考要怎麼訂下 spec，不確定之處再跟我討論。

AI

盤點現況：能改簡報的命令目前只有 text set 一條，沒有 undo；ADR-0002 定死命令集合就是產品規格；ADR-0004 定死 agent 不碰真實檔案系統、SVG 必須精簡；ADR-0008 定死一張投影片自成一體；demo 的 SVG 是裸元素，沒有 group、transform、邊界框。所以真正的問題不是「要哪些按鈕」，而是要新增哪些命令、SVG 要不要換一套幾何模型。

AI（提問）

這份 spec 要收哪些概念族？

還有這三族：表格、圖表、轉場（問題 3）

AI（提問）

表格、圖表、投影片切換效果，算不算在這份 spec 裡？

  • 不收，這三族另外算（推薦） — 表格圖表是「結構化資料」跟其他物件不同質；切換效果屬於效果清單那條線（ADR-0009），且 ADR-0008 已註明跨投影片效果「在這個結構下沒有位置」。
  • 切換效果也要，表格圖表不要 — 需要新 ADR 回答「跨頁效果住哪裡」。
  • 三族全收 — 表格圖表在 SVG 裡沒有原生表達，得先發明一套表達法。
使用者

用 15 歲聽得懂的話跟我說清楚。

AI

表格：SVG 只認得線和文字，沒有「表格」這種東西，得偷偷在 SVG 裡藏一份「這其實是 3×4 的表」的資料。圖表：同樣問題，還要多存數字與圖種。轉場效果：麻煩不在技術，在存哪裡——ADR-0008 規定一張投影片自己就是完整的一份，但轉場天生屬於兩頁之間，存進任一頁都會在對調頁面時跟錯人。

AI（提問）

表格、圖表、投影片切換效果──這三樣要不要進這份 spec？

  • 都不要，以後再說（推薦） — 這三樣各自都是新發明，各值得自己的 spec。
  • 只要切換效果 — 得重新回答「跨頁的東西存哪裡」這個已寫死的規矩。
  • 三樣全要 — 份量大一個量級。
使用者（回答）

表格和圖表另開一張 spec 未來再做（pending）。投影片切換效果統一讓一份投影片只有一種轉場效果。

轉場範圍定案（問題 4）

AI

「一份投影片」混了「簡報」和「投影片」兩個詞，兩種讀法會導向完全不同設計，需要先確認：全簡報共用一種轉場（存 project.json，ADR-0008 不用動），還是每頁各自帶一種（存該頁 SVG，要定義進場/離場歸屬）。

AI（提問）

轉場效果是全簡報一個設定，還是每頁各自一個？

  • 全簡報一個設定（推薦） — 存 project.json，對調兩頁、複製投影片、刪頁都不影響轉場。代價：不能「這一頁特別用推移」。
  • 每頁各自一個 — 需要新 ADR 交代為什麼這不算違反「投影片自成一體」。
使用者（回答）

全簡報一個設定（推薦）

幾何模型：一個元素的位置要怎麼寫（問題 5）

AI

現況：SVG 裡每種東西各講各的——文字說基準點，矩形說左上角＋寬高，沒有統一講法，也沒有地方寫「我轉了 15 度」。要搬移、縮放、旋轉、群組，就得先發明這個統一講法，這是整份 spec 的地基。

AI（提問）

一個元素的位置與旋轉，要怎麼寫進 SVG？

  • 每個元素包一層容器（推薦） — 一律是 <g>，位置旋轉寫在 transform，尺寸各講各的。三件事一個機制解決。代價：每個元素多一行，絕對座標要算。
  • 每個元素記一個明確方框 — 縮放意思最清楚，但同一件事存兩份會靜默不一致，且旋轉是自創屬性、違反 ADR-0001。
  • 不包容器，直接改原屬性 — SVG 最乾淨，但旋轉無解，群組搬移要改揉每個子元素。
使用者

以白話方式跟我說一下各個方案的優劣。

AI

用「相框」比喻講一遍：方案一是物件裝進看不見的相框，搬它是搬相框、轉它是轉相框，群組是相框裡再放相框——群組搬一公分只改最外面那個相框。方案二是每個物件自己記一塊方框，縮放與對齊最清楚，但方框跟 x/y 兩份真相會打架，而且旋轉屬性是自創的，別的軟體打開看不到轉。方案三維持裸屬性，SVG 最乾淨但旋轉無解、群組搬移要改揉每個子元素。判斷：方案一，因為只有它一個機制同時解決搬移、旋轉、群組，另兩個方案早晚要在半路上再長出 <g transform> 補洞。

使用者

如果我希望在 SVG 原圖打開就能看到其原樣，有沒有什麼好方案？

AI

這個要求直接把答案選出來了——而且選的是方案一。<g> 與 transform 是 SVG 核心語法，不是 Slidra 發明的，任何軟體打開都是正確樣子，包括旋轉。方案二會壞掉：自創屬性別的軟體會直接忽略，轉了 15 度的標題打開是正的。唯一要留意的是字型——那是另一題。

AI（提問）

幾何模型拍板：元素的位置與旋轉怎麼寫進 SVG？

  • 方案一：包一層相框（推薦） — 完全原生 SVG，任何軟體打開都正確。
  • 方案二：明確方框 — 旋轉是自創屬性，直接違反剛提出的要求。
  • 方案三：不包，直接改原屬性 — 靠放棄旋轉功能換原樣打開正確。
使用者（回答）

採用方案一。另開一張票把字型打包進 .slidra 中。

文字框（問題 6）

AI

SVG 的 <text> 不會自動換行，這是規格不是實作偷懶。PPT／Keynote 的文字框會自動折行，是使用者的基本預期。三條路：A 自己實作文字框（Slidra 算斷行寫成多行 tspan，別的軟體打開也正確；代價是每次改文字都要重算斷行，風險已被「字型打包」那票關掉）；B 一行一個元素（誠實但打一段話會痛不欲生）；C <foreignObject>（已被 ADR-0005 擋掉，不用考慮）。

AI（提問）

文字要不要有「文字框」（有寬度、會自動換行）？

  • A：自己實作文字框（推薦） — 使用者體驗跟 PPT 一樣，別的軟體打開也正確。
  • B：一行就是一個元素 — 打一段話極痛苦，調字級要改一堆元素。
使用者（回答）

A：自己實作文字框（推薦）

縮放語意：PowerPoint 還是 Keynote（問題 7）

AI（提問）

「拉大拉小」的定義：文字與群組被縮放時，字級要不要跟著變？

  • 拉邊改框、拉角等比（推薦） — Keynote 做法。拉邊只改框寬文字重排，拉角整塊等比縮放含字級，群組一律等比。代價：字級會出現小數。
  • 一律只改框，字級不變 — PowerPoint 單一物件預設，最可預期，但群組縮小時字不跟著縮，會爆框。
使用者（回答）

一律只改框，字級不變

AI

記下後立刻指出一個實際會壞掉的後果：群組的框是子元素框的聯集，縮到 50% 時「只改框」意味著每個子元素框位置寬高都乘 0.5、但字級不動——一個寬 400、字級 40 的兩行標題，框變寬 200 字還是 40，重排成四五行，往下溢出，整組排版當場散掉。

AI（提問）

那群組被拉大拉小時要怎麼辦？

  • 群組不能縮放（推薦） — 規則真的只有一條，但跟 PPT/Keynote 不一樣，使用者會困惑。
  • 群組例外，等比縮放含字級 — PowerPoint 實際行為，但兩套規則並存。
  • 群組也只改框，排版散掉就散掉 — 規則絕對統一，但幾乎必定得到壞掉的結果。
此處整個作廢，被使用者直接改成 Keynote 做法。使用者沒有從三個「群組縮放怎麼辦」的選項裡挑，而是直接回頭把上一題（拉大拉小的定義）從「一律只改框」改成「Keynote 做法」——群組縮放的問題因此自動消失，不需要再另外決定。
使用者

「拉大拉小」的定義：文字與群組被縮放時，字級要不要跟著變？改成以 Keynote 的方法。

SVG 合規性（問題 8）

AI

方案一是一個格式約定，但 SVG 不強制任何人這樣寫。不合規來源有三：現有 demo（裸元素）、使用者自己動手改、從 Figma／別處來的 SVG。三條路：A 嚴格拋錯＋一條使用者主動的轉換命令（規則單一，不會靜默改檔）；B 寬容、不合規元素唯讀（會出現「點得到卻拖不動」）；C 開檔自動修（靜默改寫使用者檔案，複雜插畫會被包成巨大 SVG）。

AI（提問）

不合規的 SVG 打開時要怎麼辦？

  • A：嚴格＋一條轉換命令（推薦）
  • B：寬容，不合規的元素唯讀
  • C：開檔自動修成合規
使用者（回答）

A：嚴格＋一條轉換命令（推薦）

復原模型：兩問一起定（問題 9）

AI

Slidra 現在一條 undo 都沒有。ADR-0002 定死「一次操作＝一條命令＝一步 undo」，沒定的是「上一步」是誰的上一步。C（人、agent 各自獨立堆疊）直接排除——selective undo 沒有正確解。

AI（提問）

Ctrl+Z 的「上一步」是誰的上一步？

  • B：一條時間軸，agent 一回合算一格（推薦） — 解掉「使用者想退自己的操作，得先一條條退掉 agent 剛做的十幾件事」這個場景。
  • A：一條時間軸，一條命令一格 — 最簡單，但使用者想退自己的操作很痛苦。
使用者（回答）

B：一條時間軸，agent 一回合算一格（推薦）

AI（提問）

復原要怎麼實作，歷史活多久？

  • 快照＋關檔就清空（推薦） — 每條命令前存副本，寫一次永遠正確，行為跟 PPT/Keynote 一致。
  • 反向命令＋關檔就清空 — 省空間，但每新增一條命令就多一份容易寫錯的反向邏輯。
  • 快照＋寫進 .slidra 永久保存 — .slidra 會一直變大，還要決定「留幾步」。
使用者（回答）

快照＋關檔就清空（推薦）

版面與母片：從「母片」一路走到「範本＋鎖定」

AI

「改母片全部一起變」天生違反 ADR-0003＋ADR-0008（投影片自成一體）。第一輪提三案：A 版面配置是起始範本（複製一次，之後獨立，ADR 不動，「改一次全部變」交給 agent）；B 真正的母片（顯示時合成，但單獨打開缺背景，推翻 ADR-0001）；C 母片是真的但改時烘焙進每頁（體驗像 PPT，代價是要逐屬性記錄「母片給的還是使用者改的」，這是整份 spec 最容易做壞的部分）。AI 推 A：Slidra 有 agent，「改全簡報底色」對它是一句話，不需要用複雜的繼承機制去買一個 agent 已經免費給的東西。

AI（提問）

版面配置／母片要怎麼做？

  • A：版面配置是起始範本（推薦）
  • C：母片是真的，改時烘焙進每頁
  • B：真正的母片，播放時合成
使用者

如果我選方案 C，是不是最容易讓 agent 去調整版面，因為他可以「看」到和使用者相同的頁面？

AI

這個問題的前提要修正：agent 不是「看」畫面的，它只能 cat SVG 檔讀出來。比較三方案 agent 讀到什麼：A 讀到完整一頁跟使用者看到的一樣；B 讀到的沒有底色沒有母片給的框，得自己合成，是三個裡對 agent 最不友善的；C 因為烘焙過，跟 A 完全一樣——C 的優勢不在「agent 看得到什麼」。而且 C 對 agent 其實更難用：它得看懂並維護「哪個屬性是母片給的、哪個是使用者改的」標記，多耗 SVG 大小、多一套規則、多一種弄壞的方式。

這裡是助理主動修正使用者問題裡的一個錯誤前提（agent 不看渲染畫面，只讀 SVG），而不是使用者的反轉——但它直接推翻了使用者這句話背後「C 對 agent 更友善」的假設，讓推薦維持 A 不變。
AI（提問）

ADR-0002 明文：命令必須語意化，不能是通用低階屬性操作。但樣式屬性有十幾種。三做法：一、一個屬性一條命令（最符合 ADR-0002，但會有一二十條，淹掉整份命令集）；二、一條通用的 element style set（ADR-0002 明文禁止，只是把 SVG 屬性名換成參數值，不建議）；三、按物件族分幾條、屬性當具名旗標（能力等價於做法一，命令壓到兩三條，但旗標名必須用領域詞）。AI 推做法三。

一條通用 element style set

選了通用命令，得補一件事，否則它會真的變成 ADR-0002 擔心的東西——問題不在命令有幾條，而在屬性名叫什麼、agent 怎麼知道有哪些屬性可用。做法一：屬性名用 Slidra 自己的詞彙＋一條列舉命令（agent 不用懂 SVG，值可驗證，但要維護對照表＋寫新 ADR）。做法二：屬性名直接用 SVG 名字（零維護成本，agent 大多懂 SVG，但等於放棄「agent 不必精通 SVG」這個前提，且沒有屬性表就沒有邊界，filter、clip-path 拒絕的理由也消失）。AI 推做法一。

AI

上一則我說「沒有屬性表就沒有邊界，會變成把任意 SVG 屬性寫進投影片的通道」——這個安全論點站不住。

助理自己撤回上一輪的安全論點。ADR-0010 已經認定投影片內容一律不可信，防線是 sandbox iframe，而且那份 ADR 明確拒絕伺服器端消毒（「消毒器繞過是一整族已知攻防」）。一個屬性能不能寫進去，不改變安全姿態——檔案本來就可能從別處帶著任何東西進來。白名單真正的理由不是安全，是它保護幾何模型的不變式：如果 element style set 什麼屬性都能設，agent 可以直接繞過 element move 寫死 transform 或 x，畫面看起來是對的，直到有人拖動它或加進群組，位置突然跳掉——因為現在有兩個地方在講位置。白名單擋的不是攻擊者，是「命令之間互相打架」。

併發與凍結（問題 14）

AI

現況：live-reload.ts 的事件不帶任何內容，前端收到就整份重載——這在只有 agent 改東西時沒問題，但編輯功能上線後會出事：使用者正拖著一個方塊，agent 改完另一個元素，畫面整份重載，手上的方塊跳回原位。三做法：一、拖曳期間緩衝，放手後再套用（成本低，但不保證正確只降低機率）；二、命令帶預期狀態的樂觀鎖（唯一真正正確，但 agent 思考期間人一動東西命令就失敗，得重讀重算）；三、完全不處理（場景常見但無害發生機率其實不高）。AI 推做法一。

  • 命令帶預期狀態（樂觀鎖）
  • 不處理
使用者沒有從三選項挑，而是給了第四個更乾脆的方向。「同一時間只有一個人在編輯」，衝突不是被緩解，是不存在——見下方。
使用者（回答）

agent 改動期間必須暫時 freeze 頁面

AI

凍的是編輯不是瀏覽——使用者仍可捲動、切頁、進播放模式，只是不能拖不能改。要定清楚的是「凍多久」。三做法：一、整個 agent 回合都凍（狀態最簡單，但 agent 想三十秒你就不能動三十秒，而那段時間根本不會有衝突）；二、只在執行每條命令的瞬間凍（凍結時間最短，但一回合閃十次，拖曳跨越那些瞬間依然會被打斷）；三、從第一條命令凍到回合結束（agent 思考讀檔時可以編輯，一動手就鎖到回合結束，跟「agent 一回合一格 undo」共用同一條界線）。AI 推做法三。
