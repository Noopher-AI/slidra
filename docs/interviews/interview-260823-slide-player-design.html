投影片播放器設計

使用者訪談紀錄 · 2026-08-23 · Slidra（SVG-first 簡報編輯器）· 來源：session 逐字檔

本次做成的決定

  • ADR-0007：播放 .slidra 需要安裝 Slidra；分享靠匯出（Export HTML / PDF / PPTX），不靠傳檔。取代 ADR-0005「runtime 不得依賴 server」。
  • 步驟作用域是頁內的，不是貫穿整份簡報；總步數用算的，不存起來。
  • 投影片的靜態長相＝所有效果都跑完的最終狀態。隱藏是 runtime 在播放時才做的事，永遠不寫進檔案；沒有效果的元素從一開始就在畫面上。
  • ADR-0009：動畫是投影片 SVG <metadata> 裡一份有序的效果清單，用自訂 XML 命名空間表示——仿 PowerPoint 的 <p:timing> 樹與 Keynote 的 build list，不是元素身上的屬性。步驟由清單推導，不另外儲存。
  • ADR-0008：一張投影片自成一體；對調兩頁不需要動任何第三個檔案。
  • 音訊必須掛在一個可見元素上（那是它的選取握把），維持「每個效果都指向一個元素」的不變式。
  • ADR-0010：投影片內容不可信。檢視模式不跑 script；播放模式才加 allow-scripts，絕不加 allow-same-origin。鍵盤必須由 runtime 自己接住，因為 transient activation 過不了 postMessage。
  • 側邊總覽用零 token 的 sandbox iframe 顯示真實縮圖，延遲載入。
  • 這一輪只做播放：沒有任何寫入命令、沒有 agent 參與；測試簡報刻意手寫，誠實檢驗格式是否對人友善。

Runtime 環境、全螢幕與焦點（問題 6）

AI（提問）

先查了兩個會決定答案的技術事實：transient activation 不會透過 postMessage 傳遞（主文件監聽方向鍵、postMessage 給 iframe 播音檔會失敗），所以按鍵必須被 runtime 自己接到；父文件可以對自己的 iframe 元素呼叫 requestFullscreen()，不必授予 iframe 全螢幕權限。

runtime 跑在 sandbox iframe 內，還是放棄 iframe？

  • A（建議） — 維持 iframe，播放時加 allow-scripts（絕不加 allow-same-origin），鍵盤由 runtime 自己監聽。
  • B — 放棄 iframe，SVG 直接 inline 進主文件，改用伺服器端消毒擋不可信內容。

建議 A：檢視模式維持零 token，播放模式才開 script；而且播放永遠全螢幕，螢幕上沒有東西會跟 iframe 搶焦點，「按空白鍵沒反應」的經典 bug 在這個設計下不存在。

此處的推論後來被使用者的下一則訊息推翻。使用者堅持全螢幕必須是使用者自己選的，不能寫死在程式裡；於是「播放永遠全螢幕，所以焦點不會被搶走」這個論證不成立了。AI 承認焦點問題回來了，並在同一次回應中拒絕了「主文件也監聽方向鍵當備援」的補救方案——因為那對純視覺步驟能動、對影音步驟會因 transient activation 過不了 postMessage 而失敗，結果是有些步驟能按有些不能，比壞掉更糟。最終收斂為：檢視／播放兩種模式，全螢幕是播放模式上的一個開關，可隨時切換，不是另一種模式；焦點不在播放器上時畫面要明確講出來、可點回去，絕不無聲失效。
使用者

我想要採用 A 方案，但是播放影片的時候一定要全螢幕，這個應該是要讓使用者可以自己選的。也可以不全螢幕，就直接在那個位置上面播放，也可以全螢幕播放，這應該是讓使用者自己選，而不是 default 刻在程式碼裡面的。

側邊總覽：真實縮圖（問題 7）

AI

先講一個查到、很誘人但用不了的事實：SVG 透過 <img src="..."> 載入時，瀏覽器會強制它進入靜態安全模式——不跑 script（正是要的），但也不載入任何外部資源（致命）。

這個選項在同一段話裡被自己否決。放了照片或影片 poster 的投影片，用 <img> 縮圖會缺一塊——簡報工具的縮圖缺圖等於沒有縮圖，所以這條看似零成本安全的路被排除。

側邊總覽顯示真實縮圖，還是頁碼清單？

  • A（建議） — 每頁一個零 token 的 sandbox iframe，跟現在 canvas.ts 同一套姿態，縮小顯示；資產正常載入，安全邊界不變。
  • B — 頁碼＋名稱清單，便宜但看不出哪頁是哪頁。

建議 A：縮圖是總覽存在的全部理由。代價是每頁一個 iframe，解法是 reveal.js 已給的延遲載入（只實體化視窗附近幾頁）。

效果清單的檔案格式（問題 8）

AI

位置不算選擇題：ADR-0003 說 project.json 只放 SVG 表達不了的東西，同一個理由適用——效果清單放進 project.json，單獨開啟一張投影片就會缺動畫，所以它住在該張投影片 SVG 的 <metadata> 裡。真正的選擇是格式：

  • A（建議） — 自訂命名空間的 XML 元素，例如 <slidra:effect target="el-a3f2c1" family="enter" effect="fade" start="on-click"/>。
  • B — JSON 塞在 <metadata> 的文字節點裡。

建議 A，理由是 ADR-0004（hand-readable、對 agent 友善）：整份檔案維持單一語法。
