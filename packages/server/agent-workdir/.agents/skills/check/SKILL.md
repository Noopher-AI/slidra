# 全份結構體檢

通讀整份簡報，找出常見的結構問題，逐一釘成留言告訴作者。**這個 skill 只留言，不修改任何內容**——找到問題不代表你有權限動手改。

## 觸發語

作者的訊息以 `/comotion-check` 或 `/check` 開頭。這個 skill 不吃參數，斜線後面即使有文字也不影響體檢範圍——一律照常跑完整份體檢。

## 輸入格式

不需要輸入。

## 步驟

1. **列出所有頁面**：`co-motion ls <presentation-id> slides`。
2. **逐頁讀取內容**：`co-motion cat <presentation-id> slides/00N.svg`，也 `co-motion effect list <presentation-id> slides/00N.svg` 看這一頁的動畫順序（結束碼非零代表這頁沒有動畫，不是錯誤）。
3. **對每一頁檢查以下六類問題**，發現一個就 `co-motion comment add <presentation-id> slides/00N.svg <target> '<描述>'` 釘一則留言（`target` 是問題所在的元素識別碼，抓不到特定元素就用 `page`）：
   - **錯字**：文字內容裡明顯的錯別字或漏字。
   - **標題層級不一致**：同類頁面（例如都是內容頁）的標題字級彼此不同。
   - **字級與顏色不統一**：同類頁面的內文字級或顏色彼此不同。
   - **要點過長**：單條要點文字明顯過長（超過一般口語念一口氣講不完的長度）。
   - **缺標題頁**：整份簡報沒有一頁看起來像封面／標題頁。
   - **動畫順序與版面順序不合**：`comot:effects` 的播放順序與元素在畫面上由上到下、由左到右的視覺順序不一致。
4. **全部頁面看完後**，在對話裡用固定格式列出這一輪釘的所有留言。

## 使用的命令

`ls`、`cat`、`effect list`、`comment add`。**不使用任何會改變投影片內容的命令**（`text set`、`element style set`、`slide style set` 等一律不用）。

## 回報格式

逐則列出：`第 N 頁，<target>：<問題描述>`。全部列完加一句總結（共發現幾個問題、釘了幾則留言）；一個問題都沒發現時，就回報「體檢完成，沒有發現問題」。

## 不可做的事

- **不修改任何內容**：找到問題只留言，不下任何會改變投影片內容的命令。這是這個 skill 與 `reshape` 的根本差別——`check` 找問題，`reshape` 才動手改。
- **不刪除、不修改任何既有留言**：包含其他人先前留的留言，`check` 只新增自己這一輪的留言。
- **簡報只有一頁**：照樣完整跑六類檢查，不因為頁數少就省略檢查項目。
- **某頁完全沒有文字元素**：照樣檢查——「缺標題頁」這一類問題本身就可能因此成立。
- **合法但風格特殊的頁面（例如封面刻意用不同字級）**：可以留言指出差異，但不得因此判定為必須統一而動手修改。
