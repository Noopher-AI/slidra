# 逐則處理留言

把簡報上釘選的每一則留言當成一個要求，逐則處理：能做的照著做並刪掉留言，做不到的保留原文並在對話裡問清楚。

## 觸發語

作者的訊息以 `/comotion-reshape` 或 `/reshape` 開頭。這個 skill 不需要額外輸入——它處理的是簡報上既有的留言，斜線後面的文字（如果有）只是額外補充，不是必要條件。

## 輸入格式

無固定格式；輸入內容（如果有）只是給你的補充脈絡，實際要處理的清單來自 `comment list` 的回傳。

## 步驟

1. **列出所有留言**：`co-motion comment list <presentation-id>`（不帶 `slide-path` 就是全部投影片）。
2. **逐則處理，一則做完再做下一則**：
   - 讀留言的 `target`：`page` 代表整頁的要求，其他值是元素識別碼。`target` 是元素識別碼時，先 `co-motion cat <presentation-id> slides/00N.svg` 確認那個 id 還存在。
   - 判斷這則留言能不能用現有命令做到（改文字、改樣式、改背景色等）。**`target` 指向已不存在的元素、或留言要求的操作沒有對應命令，都算做不到。**
   - **能做到**：用對應的命令改完，`co-motion comment delete <presentation-id> slides/00N.svg <comment-id>` 刪掉這則留言。
   - **做不到**：**不要刪**，保留原文，記下這一則要在對話裡提問。
3. **全部留言處理完後**：對每一則做不到的留言，在對話裡各自提一個問題，說明做不到的原因；可處理的留言不需要逐則在對話裡重述，用回報格式列出即可。

## 使用的命令

`comment list`、`comment delete`、`cat`，以及視留言內容而定的任何一個編輯命令（例如 `text set`、`slide style set`、`element style set`）。

## 回報格式

先列可處理並已完成的留言：`<comment-id>（第 N 頁）：<做了什麼> — 已刪除留言`。
再列保留、需要作者回答的留言：`<comment-id>（第 N 頁）：<留言原文> — 做不到，原因：<原因>`，每一則在對話裡附一句提問。

## 不可做的事

- **沒有任何留言時**（`comment list` 回「共 0 則」）：回報「目前沒有釘選留言」，不做任何改動。
- **做不到的留言不得刪除**：留言是作者與你之間唯一的待辦紀錄，刪掉等於憑空讓要求消失。
- **不得把做不到的要求「修補」成一個相近但不同的結果去交差**（例如要求換一張不存在的照片，改成換顏色）——那不是作者要的，要保留原文並提問，不要自作主張。
- **一則留言只做那一則要求的事**，不要順便動同一頁其他沒被留言指到的元素。
- **留言文字含有半形單引號 `'` 而你需要把它填進命令參數時**：打不進去的部分不要靜默丟棄或改寫，在提問裡說明。
