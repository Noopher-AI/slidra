### Settled decisions

任何單元都不得重開下列決定；認為某條錯誤時回報指揮官，不得自行改。

- **#23 spec 為權威，子票為下限。** #29／#30 的驗收清單與 #23 spec 對照過，無遺漏項；spec 的 story 14（圖片顯示）已由 #11/#25 的 `<base>` + `/api/raw/` 完成，不重做。
- ~~**全螢幕由父文件對 `controller.frameElement` 呼叫 `requestFullscreen()`**~~ **（已由指揮官撤銷，見 CHANGELOG replan）。改為：全螢幕的目標是包住播放 iframe 與播放控制列的容器元素**，父文件對該容器呼叫 `requestFullscreen()`；iframe 以 CSS 撐滿容器。理由：對 iframe 本身全螢幕會把它送進 top layer，父文件的控制列在全螢幕下完全點不到（Unit A 實測：真實 click 逾時，錯誤訊息為 iframe intercepts pointer events），使「雙向皆可切換」只剩 Esc 一條路。#24 已量過容器路線在三引擎皆可行。仍然不授予 iframe 任何全螢幕權限（不加 `allowfullscreen`，永遠不加 `allow-same-origin`）。
- **離開全螢幕（含 Esc）不得離開播放模式。** `fullscreenchange` 只同步 UI 狀態，絕不呼叫 `exitPlay()`。
- **全螢幕切換後必須把焦點交回播放器**（`controller.focusPlayer()`）——按鈕在父文件，點它會搶走焦點，不交回就等於方向鍵失效。
- **媒體的推導留在父文件。** runtime 維持「笨」的姿態：`player-plan.ts` 由 SVG 算出媒體提示，runtime 只施加。新契約：`PlayerPlan.media: Record<string, { src: string; kind: "video" | "audio" }>`，key 為效果的 target。
- **媒體種類由副檔名判定，允許清單且無歧義**：video = `.mp4` `.m4v` `.mov` `.webm` `.ogv`；audio = `.mp3` `.m4a` `.wav` `.opus` `.oga` `.aac`。`.ogg` 與其他未列副檔名一律拋錯並在畫面說明（要作者改用 `.oga`／`.ogv`），不得靜默猜測。已否決：新增 `data-comot-media-kind` 屬性（格式無謂長大）、以 HEAD 請求嗅探 MIME（非同步，會讓使用者手勢過期）。
- **`family="media"` 的效果，其 target 元素必須帶 `data-comot-media`**；沒有就是損毀的簡報，拋錯，不得略過。
- **播放呼叫必須在 keydown 的同步路徑上**（ADR-0005／#30）：建立媒體元素與 `.play()` 之間不得有 await，否則手勢過期。
- **媒體元素以 `getBoundingClientRect()` 對齊佔位元素**，絕對定位疊在 `document.body` 上；不用 `<foreignObject>`（ADR-0005）。
- **媒體疊層必須在視窗尺寸改變時重新定位。** 這是 #29 造成的跨單元事實：進入全螢幕不會重建 iframe 文件，只會把它變大，不重新定位就會錯位。
- **離開投影片時媒體必須停止**：目前的機制是 `renderPlay()` 重寫 `srcdoc`，文件被丟棄。這是假設，必須用真實音檔實測；若不成立，改由父文件在重建前送出停止指令（canvas.ts 屬 Unit B）。
- **測試用真實媒體二進位檔**，不用 mock。以 ffmpeg 產生（產生的是二進位資產，不是投影片；#23 的「必須手寫」約束針對投影片與效果清單）。**不得**用 `--autoplay-policy=no-user-gesture-required` 之類的旗標繞過自動播放政策——那會讓「播放帶聲音成功」這條驗收變成假的。Playwright 內建 Chromium 可能不含 H.264/AAC，優先用 webm/opus，且要以實測（currentTime 前進）證明而非假定。
